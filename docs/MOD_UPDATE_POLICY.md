# Marketplace Update Policy

DOOM compares the latest published semantic version shown by the API with the installed version and labels a different catalog release for review. Updates are allowed only when the target semantic version is strictly newer and the mod has been disabled. The app validates the downloaded archive with the existing importer, confirms package identity and checksum, and performs a journaled file replacement followed by a Room metadata transaction. The old file is retained until Room confirms the new metadata. If the process stops before commit, startup recovery restores the old file when Room still references its hash; if Room references the new hash, recovery completes cleanup. Uncertain states preserve the recovery marker and surface an error.

The settings JSON row and prior capability grants are preserved. New capability IDs are not granted automatically. The updated mod remains disabled and must pass activation checks again. No downgrade or post-commit rollback is offered. Existing setting values are validated against the new schema when read; invalid or removed settings fall back to declared defaults. The file replacement is recoverable during the commit, but the user cannot roll back after a successful commit.
