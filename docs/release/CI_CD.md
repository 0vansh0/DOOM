# Ci Cd

Workflows under `.github/workflows` run Android JVM tests, debug assembly, CLI, builder, portal, marketplace and npm audit on pull requests. Marketplace CI uses disposable PostgreSQL and fixture storage. The manual candidate job builds unsigned binaries and computes local checksums; those artifacts are not distributable. The separate `signed-release-verification.yml` is manual-only, main-branch-only, uses the `approved-release` GitHub Environment and environment secrets, runs tests before signing, verifies APK/AAB certificate fingerprints, records source revision/checksums in the job summary, and does not upload or publish artifacts.

Repository administrators must configure `approved-release` with required reviewers, protected environment secrets (`DOOM_KEYSTORE_BASE64`, `DOOM_STORE_PASSWORD`, `DOOM_KEY_ALIAS`, `DOOM_KEY_PASSWORD`, `DOOM_APPROVED_SIGNER_SHA256`, and `DOOM_MARKETPLACE_PRODUCTION_BASE_URL`), and main-only deployment branch restrictions before signed runs can happen. That GitHub-side policy cannot be enforced or verified from this source checkout. Existing jobs use read-only repository permissions and do not deploy. A repository administrator must also enable required status checks and protect the release branch after validating hosted runs.
