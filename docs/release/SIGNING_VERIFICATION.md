# Signing verification

The exact required environment variables are `DOOM_KEYSTORE`, `DOOM_STORE_PASSWORD`, `DOOM_KEY_ALIAS`, and `DOOM_KEY_PASSWORD`. The independent signer pin is additionally required as `DOOM_APPROVED_SIGNER_SHA256` or Gradle property `doomApprovedSignerSha256`. A signed build also requires `doomMarketplaceProductionBaseUrl` or `DOOM_MARKETPLACE_PRODUCTION_BASE_URL` naming a non-local HTTPS endpoint that is not `.invalid` and contains no embedded credentials/query/fragment. The keystore must be outside the repository; the Gradle gate rejects debug signing identities and requires the certificate SHA-256 to match the independent pin.

In this execution, none of the four signing variables or the approved fingerprint was configured, and no production HTTPS endpoint was configured. `gradlew.bat :app:checkReleaseSigning` failed closed with the missing production endpoint message; a signed assemble/bundle invocation also failed at the signing task because the four signing variables were missing. No password, key, or fingerprint was printed. No production keystore was created.

Unsigned beta.2 verification succeeded, but `apksigner verify --verbose --print-certs app/build/outputs/apk/release/app-release-unsigned.apk` reported `DOES NOT VERIFY`, and `jarsigner -verify -verbose -certs app/build/outputs/bundle/release/app-release.aab` reported `jar is unsigned`. These outcomes confirm they are unsigned and unsuitable for installation or distribution.

The new manually dispatched `.github/workflows/signed-release-verification.yml` builds only from `main`, uses an `approved-release` GitHub Environment, verifies the approved certificate on APK and AAB, and writes checksum/revision information to the job summary without uploading artifacts. The protected environment must provide `DOOM_KEYSTORE_BASE64`, `DOOM_STORE_PASSWORD`, `DOOM_KEY_ALIAS`, `DOOM_KEY_PASSWORD`, `DOOM_APPROVED_SIGNER_SHA256`, and `DOOM_MARKETPLACE_PRODUCTION_BASE_URL`. Repository administrators must configure required environment reviewers, protected environment secrets, and branch restrictions before the workflow can provide an approval gate. That repository-level protection was not inspectable here, and the workflow was not run.

For future signing, obtain the already-approved channel identity and independent certificate fingerprint, store secrets in the protected CI environment or a secure local secret manager, retain encrypted offline keystore backups with separate password custody, and verify a recovery copy. Direct APK signing and Play upload signing identities are distinct channel decisions. Never replace an established key to clear a failed build.
