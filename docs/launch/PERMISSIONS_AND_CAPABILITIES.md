# DOOM permissions and capabilities guide

This maps the current Android manifest to user-visible behavior. Android version/OEM policy can change prompts and behavior; the app's compatibility and permission status should be checked on the actual device.

| Declaration/access | Purpose | Optional? / if denied | Revocation |
|---|---|---|---|
| `INTERNET` | Account registration/login, marketplace catalog/download, and consented feedback submission. | Network-dependent features cannot connect; installed local mods can still run according to their local requirements. Android treats this as a normal install-time permission. | Disable network access for DOOM in system settings where supported, or use offline mode. |
| `VIBRATE` | User-approved mod actions that use the haptics executor. | Optional mod effect; vibration is skipped/denied according to executor outcome. Normal permission, no runtime prompt. | Disable vibration/haptics in app or device settings. |
| `SYSTEM_ALERT_WINDOW` | Draw an explicitly requested DOOM visual overlay above other apps. | Optional; no overlay is displayed without special access. This is separate from a mod's capability approval. | Android Settings → Apps → Special app access → Display over other apps; exact menu varies by OEM. |
| `WRITE_SETTINGS` | DOOM's fixed screen-timeout adjustment and restore operation. It is app-initiated and is not exposed to community mod definitions or Shizuku shell operations. | Optional; screen-timeout write is unavailable without Android's Modify system settings special access. | Android Settings → Apps → Special app access → Modify system settings. |
| `POST_NOTIFICATIONS` | Runtime notification permission on Android 13+ for user-visible notification behavior, including supported foreground-service scenarios. | User may deny; the app must respect the result and Android foreground-service restrictions still apply. | Android Settings → Apps → DOOM → Notifications. |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_SPECIAL_USE` | Platform declarations for the user-started, user-stoppable overlay foreground service and its declared special-use subtype. These are manifest declarations, not standalone runtime consent prompts. | Android/OEM background and service policy still governs availability. The service is not silently started by an imported mod. | Stop the service in DOOM or Android system UI; revoke the feature's prerequisite access in Settings. |
| Shizuku API permission/provider | Connect to the official Shizuku service only after the user installs/starts that optional service and explicitly authorizes DOOM. | Entirely optional for ordinary no-root mods. No imported mod receives Shizuku Binder/shell access; current adapter exposes a user-run diagnostic only. | Revoke DOOM in Shizuku's app list or stop the service. |

Community mod packages declare named DOOM capabilities. A user approval is not an Android permission grant, and neither is a Shizuku grant. DOOM checks capability approval, platform permission, compatibility and trusted executor independently. If a check fails, that operation should be unavailable with a reason while unrelated eligible mods continue.
